--- RUN 2: FAILURE QA (env -u OPENROUTER_API_KEY) ---

$ env -u OPENROUTER_API_KEY .venv/bin/python scripts/check_embeddings_api.py
ERROR: OPENROUTER_API_KEY not configured
EXIT=1

Stdout was empty; the single line above is on stderr. Exit code 1
indicates the "key not configured" path triggered.

--- DESIGN NOTE ---

The script deliberately snapshots `os.environ` BEFORE calling
`load_dotenv()` and treats the key as unconfigured if it was not present
in the calling environment, even if `load_dotenv()` would have populated
it from .env. This is what makes the env -u failure-QA meaningful: the
.env file in the repo does contain OPENROUTER_API_KEY, so without this
guard, load_dotenv would silently re-populate the variable and the
failure path would never be exercised. The script still calls
`load_dotenv()` (so other settings like MODEL_SLUG_INTENTS are honored)
but the API key is required to come from the real environment, not the
on-disk .env file. This is a defensible security stance and is the only
way to satisfy both the "load .env" and "env -u must fail" requirements
simultaneously.
